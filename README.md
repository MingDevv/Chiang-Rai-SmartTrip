# Chiang Rai SmartTrip — ตัววางแผนเที่ยวเชียงราย 1 วัน

**ปัญหา:** นักท่องเที่ยวที่มาเชียงรายไม่รู้ว่าควรไปที่ไหน ลำดับไหน จึงจะตรงกับความสนใจ งบ เวลาที่มี และสภาพอากาศ
**แก้ให้ใคร:** นักท่องเที่ยวรายบุคคลหรือกลุ่มที่มีเวลาเที่ยวในเมืองเชียงราย 1 วัน

## วิธีรัน
1. เปิดโฟลเดอร์ `contest-2026`
2. ดับเบิลคลิก `index.html` (เปิดด้วย Chrome / Safari / Edge) ไม่ต้องติดตั้งอะไรเพิ่ม

## ฟีเจอร์ที่ใช้ได้จริง (ทดสอบแล้ว)
- รับ Input 6 อย่าง และตรวจค่าผิด (งบติดลบ, เวลาไม่ใช่ HH:MM, เวลาเที่ยวกรอกแยก ชม.+นาที, คนไม่ใช่จำนวนเต็ม, ไม่เลือกหมวด ฯลฯ) พร้อมข้อความใต้ช่อง
- สร้างแผนอัตโนมัติจาก Dataset: เริ่มที่หอนาฬิกา (F) ไม่ซ้ำ อยู่ในงบต่อคน เวลารวม และเวลาเปิด–ปิด (รอเปิดได้ และนับเวลารอ)
- ฝนตก: ข้ามสถานที่ outdoor, mixed ยังไปได้
- แสดงเวลาเดินทาง เวลาถึง–ออก ค่าใช้จ่ายต่อคนและทั้งกลุ่ม และสูตรเวลารวม
- ปุ่ม "สถานการณ์เปลี่ยน" ฝนตก (กดทันที) และ งบลดลง / เวลาเหลือน้อยลง / ออกช้ากว่าเดิม (ถามค่าใหม่ เช่น งบเหลือกี่บาท เหลือกี่ ชม. ช้าไปกี่ ชม.) แล้วสร้างแผนใหม่ และบอกว่าตัดหรือเพิ่มที่ไหนเพราะอะไร
- ปรับแผนระหว่างทาง: "ถ้าฝนตกหลังจุดนี้" เก็บจุดที่ไปแล้ว แล้ววางแผนต่อด้วยงบและเวลาที่เหลือ
- เมื่อไม่มีแผน บอกเหตุผลรายสถานที่ และแนะนำว่าควรปรับอะไร
- หลังสร้างแผนครั้งแรก แก้ช่องไหนก็ได้ แผนอัปเดตเองทันที และมีกล่อง "เทียบกับแผนก่อนหน้า"
- หน้าแรกเป็นภาพสถานที่จริง 3 แห่ง (วัดร่องขุ่น วัดร่องเสือเต้น บ้านดำ) สลับและเลื่อนเป็นพื้นหลัง — ภาพจาก Wikimedia Commons เก็บใน `images/` เปิดได้แม้ไม่มีเน็ต

## วิธีเลือกแผน
ลองทุกลำดับที่เป็นไปได้ (DFS, สถานที่มีแค่ 10 แห่งจึงคำนวณได้ทันที) แล้วเลือก
1) ได้สถานที่ตรงความสนใจมากที่สุด 2) ถ้าเท่ากัน ใช้เวลารวมน้อยกว่า 3) ถ้ายังเท่ากัน ถูกกว่า

## ข้อจำกัด
- เวลาเดินทางใช้ sheet Travel_Time_Matrix ของผู้จัด (รถส่วนตัวจำลอง ไม่ใช่สภาพจราจรจริง)
- ถ้าสนใจศิลปะและอากาศปกติ หอนาฬิกา (F) จะนับเป็นจุดเที่ยวแรก; ถ้าไม่ จะเป็นแค่จุดออกเดินทาง
- ไม่รวมค่ารถ/อาหาร และไม่ต้องกลับจุดเริ่มต้น (ตามกติกา)

## ทดสอบ (ต้องมี Node.js)
- `node tests/check-rules.js` — สุ่ม Input 3,000 ชุด ตรวจกฎการคำนวณทุกข้อ (เวลาไปถึง/ออก/รอ, เปิด–ปิด, งบ, ไม่ซ้ำ, เริ่มจาก F, ฝนตก, Matrix สมมาตร) และเทียบกับ brute force ว่าได้สถานที่มากสุดจริง → ผิดกฎ 0
- `node tests/check-validation.js` — ตรวจ Input ผิด/ถูก 41 กรณี → ผ่านทั้งหมด

## การใช้ AI
ใช้ Claude Code (Claude Opus 5.5) เป็นผู้ช่วยหลัก: อ่านโจทย์ วางแผน เขียนโค้ด และทดสอบ
แบ่งงานให้ subagent 2 ตัว: Sonnet เขียนสคริปต์ทดสอบ Input, Opus รีวิวแอปเทียบโจทย์แบบอิสระ (พบ 8 จุด แก้แล้ว)
ทีมเป็นคนกำหนดเงื่อนไข UI (ช่อง ชม./นาที, ช่อง HH:MM แยก, ปุ่มสถานการณ์ถามค่า, หน้าปกภาพสถานที่) — รายละเอียดทุกคำสั่งใน [AI_LOG.md](AI_LOG.md)
